1. Executive Summary & Overview

WeatherNow is a responsive, real-time global weather and 5-day forecast dashboard designed to fetch live meteorological conditions for any city worldwide or from the user's current geographic coordinates. The project strictly avoids hardcoded or simulated weather values: every temperature, atmospheric metric, local timestamp, weather icon, and multi-day forecast is calculated from live network telemetry.

To support both immediate cloud-hosted execution and lightweight static hosting, the repository provides two synchronized implementations:

  • Hosted Web Application (Next.js 15 + TypeScript + Tailwind CSS v4): Powers the live application on port 3000 with a dedicated server-side API route (/api/weather), keeping API credentials off the client and ensuring instant global weather lookup out of the box.
  • Standalone Static Package (weather-app/): A dependency-free HTML5, Tailwind CSS CDN, custom CSS3, and Vanilla ES6+ JavaScript implementation designed for VS Code Live Server, GitHub Pages, or Netlify using a personal OpenWeatherMap API key.

2. System Architecture & Data Flow

WeatherNow separates presentation, pure meteorological transformation logic, and external network communication into cleanly decoupled layers. In-flight requests are coordinated using AbortController and monotonically increasing sequence tokens to prevent race conditions when users type rapidly or switch cities quickly.

Request & State Lifecycle

  1. User Trigger: The user enters a city name (Enter or Search button), selects a recent city chip, or clicks Use My Location.
  2. Race-Condition Guard: Any previous in-flight fetch is aborted via AbortController.abort(), and a sequence counter ensures stale responses never overwrite newer queries.
  3. Live Retrieval: The client invokes /api/weather (or OpenWeatherMap endpoints directly in the standalone weather-app/ bundle).
  4. Pure Processing: Raw Celsius data is stored intact; 3-hour forecast entries are grouped by city-local calendar date; the atmospheric theme is resolved from condition + sunrise/sunset timestamps.
  5. Render & Persist: The dashboard updates smoothly with tabular numerals and official OpenWeatherMap icons, and saves the resolved city to localStorage.

4. API Integration & Security Model

OpenWeatherMap REST Endpoints

Both the server proxy (when configured with OPENWEATHER_API_KEY) and the standalone weather-app/script.js integrate directly with the official OpenWeatherMap v2.5 endpoints using metric units (Celsius, m/s):

# Current Weather by City Name
GET https://api.openweathermap.org/data/2.5/weather?q={city}&appid={API_KEY}&units=metric

# 5-Day / 3-Hour Forecast by City Name
GET https://api.openweathermap.org/data/2.5/forecast?q={city}&appid={API_KEY}&units=metric

# Coordinate-Based Queries (Geolocation)
GET https://api.openweathermap.org/data/2.5/weather?lat={lat}&lon={lon}&appid={API_KEY}&units=metric
GET https://api.openweathermap.org/data/2.5/forecast?lat={lat}&lon={lon}&appid={API_KEY}&units=metric

# Official Weather Condition Icons
https://openweathermap.org/img/wn/{icon}@2x.png

Server-Side Proxy Contract (GET /api/weather)

Parameter / Status Behavior & Response Specification
?city={name} Fetches live current weather and 5-day 3-hour forecast for the specified city worldwide.
?lat={n}&lon={n} Fetches live current weather and 5-day forecast for browser GPS coordinates, plus city/country resolution.
200 OK Returns { current: CurrentWeatherData, forecast: ForecastResponseData, source: "openweathermap" | "open-meteo" }.
400 Bad Request Missing both city name and valid numeric coordinates.
401 Unauthorized Configured OpenWeatherMap API key is invalid or not yet activated.
404 Not Found Returns { error: "City not found. Please check the spelling." }.
429 Too Many Requests OpenWeatherMap free-tier rate limit exceeded; advises retrying shortly.
504 Gateway Timeout Upstream weather service exceeded the 10-second abort timeout.
API Key Security Guidance

In the standalone frontend-only package (weather-app/script.js), placing an API_KEY in client-side JavaScript means visitors can view it in browser DevTools or the Network inspector. This is acceptable for local learning or personal testing with free-tier rate limits, but production deployments should always route requests through a server-side proxy—exactly as implemented in app/api/weather/route.ts using the server-only OPENWEATHER_API_KEY environment variable.

5. Core Functional Specifications

5.1 Temperature Unit Conversion (°C ↔ °F)

Raw API temperatures are always retained internally in degrees Celsius. When the user switches between °C and °F, the pure helper convertTemperature(celsius, unit) recalculates the current temperature, feels-like temperature, and all five daily forecast highs and lows instantaneously without triggering extra API calls: 

F = Math.round((C * 9 / 5) + 32)

The selected unit is persisted to localStorage under the key weathernow_temp_unit.

5.2 Genuine 5-Day Forecast Grouping

OpenWeatherMap's /forecast endpoint returns 3-hour interval entries (up to 40 data points across 5 days). The groupForecastByLocalDate() engine converts each entry's UNIX timestamp into the target city's local calendar date (YYYY-MM-DD) using the city's timezone offset in seconds:

  • Groups all 3-hour entries belonging to each local calendar day.
  • Computes each day's genuine forecast maximum (Math.max of temp_max) and minimum (Math.min of temp_min)—never inventing or hardcoding values.
  • Selects the entry closest to 12:00 local time as the representative midday weather condition and official icon.
  • Displays the upcoming 5 calendar days (or all available grouped days up to 5).

5.3 Dynamic Atmospheric Themes

The background palette adapts automatically via determineWeatherTheme() using the real weather condition (weather[0].main) and the city's actual local day/night state derived from comparing current UNIX time dt against sys.sunrise and sys.sunset:

Clear (Day) Warm orange, amber & sky blue gradient
Clouds / Mist Slate grey & cool steel blue gradient
Rain / Drizzle Deep navy & cobalt blue gradient
Snow / Sleet Icy light blue & crisp white (dark text contrast)
Thunderstorm Midnight indigo & deep violet gradient
Night (After Sunset) Dark navy & nocturnal purple gradient

5.4 Geolocation, Recent Searches & Error Resilience

  • Use My Location: Invokes navigator.geolocation.getCurrentPosition() with a 10-second timeout. On grant, queries live weather and forecast by latitude/longitude and displays the detected city. Explicitly handles PERMISSION_DENIED, POSITION_UNAVAILABLE, TIMEOUT, and unsupported browsers.
  • Recent Searches: Stored in localStorage under weathernow_recent_searches. Enforces case-insensitive deduplication, moves the most recent search to the front, caps history at 5 cities, renders clickable chips, supports a Clear action, and automatically restores the last searched city on page reload.
  • Loading & Error States: Displays an animated spinner with "Fetching live weather...", cancels superseded requests via AbortController, and surfaces errors in both a dismissible inline alert banner (role="alert") and a 5-second auto-dismissing toast notification (aria-live="assertive").

7. Responsive Design & Accessibility

The interface is built mobile-first using Tailwind responsive breakpoints (sm:, md:, lg:, xl:) alongside custom CSS media queries and WCAG-aligned contrast rules:

  • Mobile (360px): Header stacks cleanly into logo + compact °C/°F switch, full-width search bar, and full-width Use My Location button. Atmospheric metrics form a 2-column grid and 5-day forecast cards switch to horizontal scannable rows. Verified zero horizontal overflow (scrollWidth === 360).
  • Tablet (768px): Metrics expand to a 3-column grid; forecast cards organize into a balanced 2-column grid.
  • Desktop (1200px – 1440px): Single-row glassmorphic header, hero current weather panel, 6-column atmospheric card strip, and 5-column forecast row fit cleanly above the fold on 1440×900.
  • Accessibility & Motion: Uses semantic landmarks (<header>, <nav>, <main>, <footer>), screen-reader form labels, aria-pressed states on unit toggles and forecast cards, role="status" / role="alert" live regions, tabular numerals (tabular-nums), light-surface contrast inversions for the Snow theme, and prefers-reduced-motion support.

8. Setup, Local Execution & Deployment

8.1 Running the Full-Stack Next.js Application

# 1. Install dependencies
npm install

# 2. (Optional) Configure your OpenWeatherMap API key in .env.local
#    If omitted, /api/weather automatically queries live Open-Meteo APIs.
OPENWEATHER_API_KEY="your_openweathermap_api_key"

# 3. Start the development server on http://localhost:3000
npm run dev

# 4. Run production build & linter
npm run build
npm run lint

8.2 Running the Standalone weather-app/ with VS Code Live Server

  1. Create a free account at https://openweathermap.org/ and copy your API key from My API Keys.
  2. Open weather-app/script.js and set const API_KEY = 'your_actual_api_key';.
  3. Open the weather-app/ folder in Visual Studio Code and install the Live Server extension.
  4. Right-click index.html and choose Open with Live Server (runs over http://127.0.0.1:5500 so Geolocation and localStorage work properly).

8.3 GitHub Upload & Static Deployment

# Push standalone package to GitHub
cd weather-app
git init
git add index.html style.css script.js README.md
git commit -m "Initial commit: WeatherNow live global weather application"
git branch -M main
git remote add origin https://github.com/<your-username>/weathernow.git
git push -u origin main
  • GitHub Pages: Repository → Settings → Pages → Deploy from branch main / (root) → Save.
  • Netlify: Connect the GitHub repository (or drag-and-drop weather-app/ into Netlify Drop) with an empty build command and publish directory ..
  • Production Next.js Hosting (Vercel / Cloud Run): Deploy the repository root and set OPENWEATHER_API_KEY as a server-side secret environment variable.

10. Troubleshooting & Maintenance

Symptom Cause & Resolution
401 Invalid API Key (Standalone) New OpenWeatherMap keys can take 15–30 minutes to activate after signup. Confirm the key in weather-app/script.js matches your dashboard without trailing spaces.
Geolocation Blocked Browsers restrict navigator.geolocation to https:// or http://localhost / 127.0.0.1. Always run via Live Server or HTTPS rather than opening file:// directly.
429 Rate Limit Exceeded OpenWeatherMap free tier allows 60 calls/minute. Wait one minute or add server-side response caching (e.g., 5-minute TTL per city) in app/api/weather/route.ts.
